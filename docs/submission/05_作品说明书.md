# 作品说明书：答辩预演官

> AI 三评委答辩模拟与复盘报告 · TRAE AI 全国大学生创造力大赛 · 学习科研赛道
> 线上体验：https://trea-ai-creativity-p4nr.netlify.app/

## 1. 一句话

上传论文或开题报告，三位不同视角的 AI 评委轮流追问，结束后给出四维评分、逐题点评、可照读的参考话术与复盘清单——把「答辩前没人问我」变成「先被问穿一遍」。

## 2. 问题与用户

**痛点是具体的**：开题、中期、毕业答辩各只有一次机会，但准备过程普遍是「背熟 PPT + 看经验帖」。真实评委的追问角度（方法为什么这样选、创新点与已有方案差在哪、结论的边界在哪）几乎没有人提前演练。请师兄师姐模拟一次，成本高、覆盖窄，而且对方往往不是你所在领域。

**目标用户**：本科生与研究生的答辩准备者，以及需要给学生做预答辩指导的青年教师。
**使用时机**：答辩前 3–7 天，一场 15 分钟的模拟 + 按报告改材料。

## 3. 功能清单

| 模块 | 能力 |
| --- | --- |
| 建场 | 答辩类型（开题/中期/毕业/自定义）、学科（含自定义）、严格度、目标题量、限时、参与评委 |
| 材料 | 多文件同时上传（PDF / PPTX / Word / Excel / Markdown / JSON / CSV / TXT），或直接粘贴文本；浏览器内解析，原文不上传 |
| 材料画像 | 提炼「研究问题—方法—创新点—关键证据—局限—关键词」 |
| 答辩 | 三评委轮换提问、最多两层追问、请求提示、跳过当前题、随时结束 |
| 报告 | 四维评分与雷达图、高危问题 Top 5、逐题点评、可照读参考话术、复盘清单 |
| 导出 | PNG / JPG / PDF / Word / Markdown，导出时自动展开全部逐题点评 |
| 历史 | 回看报告、再练一场（可沿用或更换材料）、删除需二次确认 |
| 账号 | 邮箱注册（含验证）、GitHub 一键登录、忘记密码；登录后本地↔云端双向同步 |
| 会员 | 免费额度（单文件 5MB / 整场 10MB / 带文件答辩 1 次）、VIP（20MB / 50MB / 不限次 / GitHub 仓库导入） |

## 4. 技术架构

```
浏览器
├─ React 19 + TypeScript + Vite 8 + Tailwind CSS 4 + Zustand + React Router
├─ 材料解析：pdfjs-dist / jszip / xlsx（全部本地执行，原文不出本机）
├─ 报告导出：html-to-image（图片）、jspdf（PDF，按需加载）、自研 Word/Markdown 生成
└─ Supabase JS（登录态、历史同步、会员权益）

服务端（Serverless）
├─ /api/llm：代理阿里云 MaaS 的 OpenAI 兼容流式接口
│   · 服务端构建 prompt，API Key 永不下发前端
│   · enable_thinking=false，单次 5–8 秒，规避函数超时
│   · 单日调用上限 + 前端缓存，保护额度
└─ /api/github-import：仅 https://github.com/{owner}/{repo} 公开仓库
    · 抓取仓库简介 + README + 顶层目录，最多 2 万字符
    · 用用户 JWT 调 Supabase RPC 校验 VIP，不保存任何 token

数据（Supabase Postgres）
├─ profiles：plan（free/vip）、vip_expires_at、免费上传额度
├─ defense_sessions：答辩记录（RLS 仅本人可读写）
├─ vip_orders：订单（用户只能插 pending，管理员改 paid 触发自动开通）
└─ 关键函数：is_vip()、claim_free_upload()、apply_vip_order()
```

## 5. 关键设计决策

**为什么材料必须在浏览器内解析**：未公开的论文、专利数据一旦上传就有泄露风险。把解析放在前端，服务端只收到文本片段，既降低合规风险，也简化了后端。

**为什么用三类人格化评委而不是一个通用评委**：真实答辩的追问是有「性格」的。方法论派抠变量与样本，创新性质疑派比差异，应用价值派问落地。分开建模，追问才不是泛泛而谈。

**为什么免费额度要服务端校验**：前端 localStorage 可以清缓存绕过。登录用户的「带文件答辩 1 次」由 Supabase RPC 在开始答辩时抢锁，清理缓存无效。

**为什么会员是演示模式**：参赛作品不应出现真实收款引导。默认 `VITE_VIP_DEMO=true` 隐藏收款码并标注演示环境，权益与订单流程仍可完整演示。

## 6. 质量与验证

- **自动化测试**：27 个测试文件、110 个用例（Vitest + Testing Library），覆盖权益判定、报告组装、导出、材料页与历史页交互。
- **构建**：`npm run build` 通过 TypeScript 严格类型检查。
- **线上验收**：7 项浏览器端真实操作验收全部通过（大小限制、免费额度、VIP 门槛、历史与报告再练限制、会员页）。
- **接口自检**：`/api/llm` 流式返回正常；`/api/github-import` 未登录 401、非 VIP 403。

## 7. 数据与隐私

- 原始文件不上传，只在浏览器内解析；服务端仅接收用于提问与点评的文本片段。
- 会话与报告默认存本机 localStorage，可随时删除或清空。
- 登录后同步到 Supabase，行级安全策略保证只能访问自己的数据。
- API Key 仅存在于服务端环境变量，前端代码与构建产物中不含密钥。

## 8. 已知局限与后续规划

**局限**：样本量小（20 人对照实验）；评分依赖模型判断，尚未与真实评委打分做一致性检验；艺术设计类以作品集为主的答辩覆盖不足；未接入真实支付。

**规划**：引入「评委一致性校准」（同一材料多次生成取稳定性）；支持语音作答与语速分析；增加学科专属题库；开放教师端查看学生模拟记录。
