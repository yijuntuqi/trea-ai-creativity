# 答辩预演官 — 产品设计 Spec

- 日期：2026-11-24
- 状态：待用户 review
- 作者：张异 + TRAE
- 参赛：TRAE AI 全国大学生创造力大赛 · 学习科研赛道
- 截止：2026-12-25

## 1. 背景与目标

学生在论文答辩、项目结题、课程汇报前，普遍缺少高质量的模拟提问环境：导师时间有限，同门互问过于客气，自己练习又不知道会被问什么。多数人直到答辩现场才第一次面对追问压力。

**答辩预演官**让学生上传论文或答辩 PPT，由 AI 扮演 3 位风格不同的评委进行多轮追问和现场打分，最后生成一份可复盘、可分享的《答辩预演报告》。

### 成功标准

1. 用户从进入首页到拿到第一份报告，全程不超过 15 分钟。
2. 报告能明确指出"最可能被问倒的 5 个问题"并给出参考话术。
3. 无 API Key 时可用 mock 数据完整走通全流程；有 Key 时真实模型输出可用。
4. 公网链接可访问，移动端可完成一场预演。
5. 比赛提交材料齐全：链接、视频、≥3 张截图、≥3 个 Session ID。

## 2. 用户与场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 本科毕业生 | 毕设答辩前 1–2 周 | 知道评委会问什么、怎么答 |
| 硕士生 | 学位论文答辩 | 方法细节与创新点的抗压测试 |
| 项目团队 | 大创/竞赛结题答辩 | 应用价值与可行性质疑 |
| 课程学生 | 课程展示/汇报 | 快速练习表达与控时 |

## 3. 范围

### MVP 必做

- 答辩类型、学科、严格度、限时配置
- PDF / PPTX 浏览器本地解析，或粘贴摘要与大纲
- 生成 3 位评委画像（方法论派 / 创新性质疑派 / 应用价值派）
- 模拟答辩：逐题提问、多轮追问、单题计时、跳过与重答
- 四维评分与《答辩预演报告》
- 历史记录（localStorage）与预置演示场
- TTS 朗读评委提问，默认关闭
- 深色学术风视觉与移动端适配
- Netlify 部署 + 阿里云 MaaS 代理

### 明确不做

- 真实语音识别、录音上传
- 账号体系、后端数据库、多人协作
- 视频分析、PPT 版式还原
- 支付、社区、排行榜
- 多语言（仅中文）

## 4. 核心用户流程

```
首页 → 建场配置 → 上传/粘贴材料 → 生成评审画像
   → 模拟答辩（6–10 题，可追问）→ 生成报告 → 复盘/分享
```

1. **首页**：价值主张 + "立即预演" + 3 张评委卡 + 示例报告入口。
2. **建场**：选择答辩类型、学科、严格度、限时；一键使用示例材料。
3. **材料**：拖拽 PDF/PPTX 或粘贴文本；显示解析字数；本地处理提示。
4. **画像**：展示提取出的 5 个要点和 3 位评委，可调整严格度后开始。
5. **答辩**：评委逐题发问，用户作答，可请求追问、跳过、查看提示；单题倒计时。
6. **报告**：总分、雷达图、逐题点评、高危问题 Top 5、参考话术、复盘清单。
7. **历史**：本地保存过往场次，可回看报告、删除记录。

## 5. 信息架构与路由

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 首页 | 入口、评委展示、示例报告 |
| `/setup` | 建场 | 配置表单 |
| `/material` | 材料 | 上传/粘贴、解析预览 |
| `/session/:id` | 答辩室 | 评委、对话、计时、控制栏 |
| `/report/:id` | 报告 | 评分、点评、导出 |
| `/history` | 历史 | 本地场次列表 |

移动端：答辩室改为单列，评委与计时器收进顶部条；报告单列滚动。

## 6. 功能规格

### 6.1 建场配置

- 答辩类型：本科毕设 / 硕士学位 / 项目结题 / 课程汇报
- 学科：理工 / 人文社科 / 经管 / 医学 / 艺术设计 / 其他
- 严格度：温和（鼓励为主）/ 标准 / 压力（连续追问）
- 限时：8 / 15 / 25 分钟
- 题目数量由限时推导（8 分钟约 6 题，15 分钟约 8 题，25 分钟约 10 题）
- 所有配置写入 `Session.config`

### 6.2 材料解析

- 支持：`.pdf`、`.pptx`、纯文本粘贴
- PDF 使用 `pdfjs-dist` 提取文本层；扫描版 PDF 提示"未识别到文本，请粘贴大纲"
- PPTX 使用 `jszip` 读取 `ppt/slides/slide*.xml`，提取 `<a:t>` 文本并按页拼接
- 解析结果在前端截断至约 6000 tokens（约 4000 汉字），保留开头、方法与结论段落
- 计算材料指纹 `hash`（文本 SHA-256 前 16 位），用于画像缓存
- 文件不离开浏览器；页面上明确提示

### 6.3 评审画像

AI 从材料中提取结构化要点：

```json
{
  "topic": "研究主题",
  "problem": "研究问题",
  "method": "方法与数据",
  "innovation": ["创新点1", "创新点2"],
  "evidence": ["关键证据/实验结果"],
  "limitations": ["局限1", "局限2"],
  "keywords": ["关键词"]
}
```

三位固定评委（人设 + 关注点）：

| 评委 | 关注点 | 提问风格 |
|---|---|---|
| 方法论派 · 严谨型 | 方法合理性、样本、对照、统计 | 追问细节，要求给数据 |
| 创新性质疑派 · 犀利型 | 与已有工作的差异、贡献边界 | 直接质疑"这算创新吗" |
| 应用价值派 · 务实型 | 落地成本、真实需求、可推广性 | 追问"谁会用、为什么用" |

画像生成失败时降级为通用画像（基于材料前 2000 字），不阻断流程。

### 6.4 模拟答辩

- 每轮由系统选择一位评委发问；同一评委不连续超过 2 题
- 每题包含：问题文本、提问意图（内部字段，用于点评）、建议作答时长
- 用户输入回答后，系统给出即时反馈（1–2 句），并决定是否追问
- 追问最多 2 层，避免无限循环
- 严格度影响：温和模式少追问、点评偏鼓励；压力模式追问率高、点评直接
- 单题计时：到点提示但不强制结束
- 控制栏：请求提示（给 1 条作答思路）、跳过、结束并出报告
- 回答为空或过短（< 10 字）时提示补充，不计入评分

### 6.5 评分与报告

四维评分（各 0–100）：

| 维度 | 权重 | 评估依据 |
|---|---|---|
| 内容准确性 | 30% | 是否答到材料中的事实与方法 |
| 逻辑结构 | 25% | 是否有层次、先结论后论据 |
| 应答深度 | 25% | 是否覆盖追问点、给出证据 |
| 表达清晰 | 20% | 简洁度、口头禅、术语解释 |

报告内容：

- 总分（加权）与等级（优秀 / 良好 / 待改进）
- 四维雷达图
- 逐题：问题、你的回答摘要、得分、点评、参考话术
- 高危问题 Top 5（得分最低或追问最多的题）
- 复盘清单（3–5 条可执行建议）
- 导出：生成分享图片（html-to-image），保存到本地

### 6.6 历史与演示

- localStorage key：`dr:sessions`，最多保留 20 场
- 首页提供"查看示例报告"，指向内置 mock 场次
- 删除单场与清空全部

### 6.7 TTS 语音播报

- 默认关闭，答辩室顶部提供开关，状态存入 localStorage
- MVP 使用浏览器 `SpeechSynthesis`（零成本、离线可用），中文语音优先
- 若阿里云 `qwen3-tts-flash` 的 OpenAI 兼容端点验证可用，则作为增强项接入 `/api/tts`；不可用不影响 MVP
- 不做语音识别，用户始终文字作答

## 7. 技术架构

### 7.1 技术栈

- 前端：Vite + React 19 + TypeScript + Tailwind CSS v4 + shadcn/ui
- 图表：Recharts（雷达图）
- 动画：Framer Motion（克制使用）
- 状态：Zustand + persist（localStorage）
- 解析：`pdfjs-dist`、`jszip`
- 后端：Netlify Functions（Node 20），单入口 `/api/llm`
- 模型：阿里云 MaaS OpenAI 兼容端点
  - 主力：`qwen3.8-flash`
  - 报告汇总：`qwen3.8-plus`
  - 可选：`qwen3-tts-flash`
- 部署：Netlify（前端 + Functions 同域）

### 7.2 目录结构（计划）

```
/
├─ src/
│  ├─ pages/            # Home / Setup / Material / Session / Report / History
│  ├─ components/       # 评委卡、对话气泡、计时器、雷达图、报告块
│  ├─ lib/
│  │  ├─ llm.ts         # 前端调用 /api/llm 的封装（SSE 解析）
│  │  ├─ prompts.ts     # 四类任务模板
│  │  ├─ parse/         # pdf.ts / pptx.ts / truncate.ts
│  │  ├─ scoring.ts     # 加权与等级
│  │  └─ storage.ts     # localStorage 读写与迁移
│  ├─ store/            # Zustand
│  ├─ mocks/            # 演示场次与固定画像
│  └─ styles/
├─ netlify/functions/llm.ts
├─ public/
├─ docs/
└─ .env.example
```

### 7.3 API 契约

`POST /api/llm`，请求：

```json
{
  "task": "portrait | question | evaluate | report | hint",
  "payload": {},
  "sessionId": "uuid"
}
```

响应：`text/event-stream`

```
data: {"delta":"..."}
data: {"done":true,"usage":{"prompt":123,"completion":45}}
```

服务端职责：

1. 校验 `task` 白名单与 payload 大小（材料 ≤ 12k 字符）
2. 根据 task 选择 system prompt 与模型
3. 注入 `MAAS_API_KEY`，转发到 MaaS `/chat/completions`，`stream: true`
4. 设置 `max_tokens`（提问 300 / 点评 400 / 报告 1500）
5. 错误统一返回 JSON：`{ error: { code, message } }`

服务端不落库、不记录用户材料内容；仅记录匿名计数用于熔断。

### 7.4 数据模型

```ts
type Session = {
  id: string
  createdAt: number
  config: { type: string; discipline: string; strictness: 'gentle'|'standard'|'press'; minutes: number }
  material: { fileName?: string; text: string; chars: number; hash: string }
  portrait?: Portrait
  messages: Message[]
  questions: Question[]
  report?: Report
  status: 'setup'|'ready'|'ongoing'|'finished'
}
```

`Question` 记录评委、问题、意图、回答、耗时、追问层级；`Report` 记录总分、四维分、逐题点评与清单。

### 7.5 Prompt 设计

- 所有任务共用“答辩评审专家”系统角色，禁止编造材料中不存在的数据
- 输出 JSON 的任务（画像、评分、报告）在 prompt 中给出严格 schema 与示例，前端做容错解析（剥离代码块、修复尾逗号）
- 提问任务输出单题，避免一次生成全部问题导致质量下降
- 追问时只携带最近 3 轮对话与当前题，控制 token

### 7.6 成本与熔断

- 单场约 8–12 次调用、15–25k tokens，flash 估算单场 < ￥0.1
- 画像按 `材料hash + 配置` 缓存，同一材料重复建场不重复调用
- 前端每日调用计数存 localStorage，超 200 次停止真实调用并提示
- Netlify Function 内做单实例内存计数兜底（非严格限流，仅防异常刷量）
- 开发与演示默认 mock，联调阶段才真调 API

## 8. 安全与隐私

- `MAAS_API_KEY` 只存在于 `.env`（本地）与 Netlify 环境变量，`.env` 写入 `.gitignore`
- 前端不出现任何密钥；仓库与构建产物不含密钥
- 材料仅在浏览器解析，仅提取后的文本会发送到模型
- 页面明确提示"材料将在本地解析，仅向模型发送文本摘要"
- 报告与历史仅存本地，提供删除入口

## 9. 视觉与交互规范

- 基调：深墨蓝（`#0B1220`）+ 暖金（`#E8B45A`）+ 冷白文字
- 意象：答辩台、聚光灯、评委席、倒计时
- 字体：标题用思源宋体（Noto Serif SC），正文用系统无衬线
- 首页：大标题 + 一句话价值主张 + 单主按钮；下方三张评委卡（头像、关注点、一句口头禅）
- 答辩室：左材料要点 / 中对话 / 右计时与当前评委；移动端单列
- 报告：像一份正式评审意见书，分数大字 + 雷达 + 逐题卡片，适合截图
- 动效：评委发问淡入、报告分数数字滚动；不使用大面积炫光
- 无障碍：对比度达标、键盘可操作、焦点可见

## 10. 错误处理与边界

| 情况 | 处理 |
|---|---|
| 无 API Key / 请求失败 | 自动切换 mock 模式并提示"当前为演示模式" |
| 模型返回非法 JSON | 一次重试；仍失败则用通用画像/本地评分兜底 |
| PDF 无文本层 | 提示粘贴大纲 |
| PPTX 解析异常 | 回退到文本粘贴 |
| 回答过短 | 提示补充，不计分 |
| 刷新页面 | 从 localStorage 恢复进行中的场次 |
| 超时/断流 | 保留已生成内容，提供重试按钮 |

## 11. 验收标准

1. 无 Key 环境下，从首页到报告全流程可完成，无报错。
2. 有 Key 环境下，画像 JSON 解析成功率 ≥ 95%，单题响应首字 < 3 秒。
3. 报告包含四维分数、雷达图、≥6 题点评、Top 5 高危问题、≥3 条建议。
4. 390px 宽度下建场、答辩、报告均可用。
5. 仓库与构建产物中搜索不到 API Key。
6. 历史记录可保存、回看、删除。
7. TTS 开关默认关闭，开启后可朗读问题，关闭后立即停止。
8. Netlify 公网链接可访问，函数正常返回流式内容。

## 12. 里程碑与交付物

按依赖顺序推进，每阶段可独立验收：

1. **骨架与视觉**：Vite + React + Tailwind + 路由 + 首页 + mock 数据
2. **材料与画像**：PDF/PPTX 解析、截断、画像生成（mock + 真实）
3. **答辩室**：提问、回答、追问、计时、提示、跳过
4. **报告与历史**：评分、雷达、点评、导出、localStorage
5. **联调与上线**：真实 API、Netlify 部署、演示数据、截图、视频脚本、README

交付物：公网链接、1–5 分钟视频、≥3 张截图、≥3 个 TRAE 开发 Session ID（指开发过程的会话记录，不是产品内的场次 ID）、项目计划书、README。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Netlify 国内访问不稳定 | 评审打不开 | 准备 Vercel / zhxt 备用链接；首页轻量化 |
| PPTX 结构差异大 | 解析失败 | 文本粘贴兜底；只提取文本不还原版式 |
| 模型提问同质化 | 体验差 | 三类评委模板 + few-shot + 严格度参数 |
| 追问失控/超时 | token 超标 | 追问最多 2 层、题数上限、max_tokens |
| 语音接口不兼容 | TTS 不可用 | 默认用浏览器 SpeechSynthesis，模型 TTS 仅作增强 |
| 开发时间紧 | 功能砍不完 | 按里程碑交付，每阶段结束都是可演示状态 |

## 14. 比赛评分对齐

| 评分项 | 对应设计 |
|---|---|
| 应用价值 30 | 答辩刚需、四类场景、报告可复用、零门槛 |
| 创新性 30 | 评审画像 + 追问链 + 四维报告闭环，非通用聊天套壳 |
| 技术实现 20 | 本地解析保护隐私、SSE 流式、缓存与熔断、容错解析 |
| 交互审美 20 | 深色学术风、评委人格化、报告可截图传播 |

## 15. 开放问题

- 阿里云 `qwen3-tts-flash` 是否提供 OpenAI 兼容音频接口，需联调时验证；不影响 MVP。
- Netlify 免费额度的函数调用与带宽是否足够比赛期访问，上线后观察。
- 是否需要"多人围观/导师点评"模式，留到赛后版本。
